# SansPost v1.0.0

First stable release of SansPost — a production-deployed real-time social platform presented as an interactive
western saloon (.NET 8, F#, SignalR, Three.js, PostgreSQL).

Live demo: https://sanspost.byst.re

## Highlights

- **Saloon 3D** — Three.js Entrance and Main Hall with real buttons for every zone, render-on-demand and a CSS/HTML
  fallback for devices without WebGL or with reduced motion. The Entrance board shows the number of registered public
  accounts against the limit.
- **BAR** — conversations in topic categories, newest/popular feeds, PostgreSQL full-text search, comment threads,
  reactions and notifications, all opened inside the hall (deep links and browser back work).
- **Wanted Board** — ranking of the most engaging conversations of the last 7 days (reactions + comments), one poster
  per author, moderation-aware (hidden content and suspended/banned authors are never promoted).
- **Music Corner** — live country stations discovered through Radio Browser; the browser streams directly from the
  station, one audio element survives navigation, at most 2 hours of active playback before a deliberate restart.
- **F# duel engine** — *The Gunslinger's Draw* rules in a pure, immutable F# library with typed results.
- **SignalR multiplayer** — real-time 1v1 duels: challenges, ready check, simultaneous hidden moves, server-authoritative
  timers, reconnect with a grace window, surrender and rematch.
- **Prestige / leaderboard** — persistent results, prestige stars, leaderboard and the "Master of the Table".
- **PL/EN** — the whole public interface in Polish and English, switched in place without losing the session, the
  open duel, the radio or the 3D scene.
- **Daily quotas** — per user per UTC day: 10 posts, 20 comments, 15 started games; stored in PostgreSQL and consumed
  atomically with the operation (a duel uses both players' quota or neither); HTTP 429 with stable codes.
- **Public account capacity** — a fixed number of public accounts (default 100); seeded demo and admin accounts do not
  take public slots; registrations are serialized in PostgreSQL.

## Production

- **Docker** — multi-stage, runtime-only, non-root image; Docker Compose with PostgreSQL and Caddy; log rotation.
- **PostgreSQL 17** — EF Core migrations applied on start; backup (`deploy/backup.sh`, retention) and restore check
  (`deploy/restore-check.sh`).
- **HTTPS** — Caddy reverse proxy with automatic certificates and zstd/gzip; trusted forwarded headers only from the proxy.
- **Security** — strict Content Security Policy, `frame-ancestors 'none'`, nosniff, Referrer-Policy, Permissions-Policy;
  cookie authentication for the UI (HttpOnly, Secure, SameSite=Lax) and JWT for the REST API; rate limits.
- **Observability** — structured JSON logs with request IDs; `/health/live` and `/health/ready` (database only).
- **Accessibility** — keyboard navigation, screen-reader names, axe-core with no critical or serious issues on the
  main screens (light/dark, PL/EN); responsive from 1440 px down to 360 px.
- **Production optimization** — render-on-demand 3D (idle main-thread work 14.9 → 0.2 ms/s), adaptive Server GC
  (lower memory), smaller publish output, immutable caching for versioned assets.

## Upgrade notes

- Additive migrations `20260929054133_DuelResults` and `20261002053244_DailyUserUsage` — back up the database before
  upgrading (`./deploy/backup.sh`).
- The previous lifetime per-account post limit is replaced by the daily quotas.

## Known limitations

- Single application instance: duel sessions, SignalR connections and rate limits live in process memory (no backplane).
- The admin moderation panel is Polish-only; the public interface is PL/EN.
- No ranked matchmaking or ELO — prestige stars count wins.
